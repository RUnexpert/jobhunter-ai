# JobHunter AI

Полноценное локальное веб-приложение для поиска вакансий, AI-анализа и подготовки откликов. Next.js App Router + React + strict TypeScript, Tailwind 4, shadcn-style Button/Radix, TanStack Query, React Hook Form/Zod, Recharts; PostgreSQL/Prisma, Redis/BullMQ, отдельный worker, SSE, SMTP, OpenAI-совместимый API и Ollama.

**Важное ограничение интеграции:** в public OpenAPI hh.ru, проверенной 27.10.2026, нет документированного POST отклика соискателя и списка собственных резюме. Поэтому приложение действительно ищет и анализирует вакансии, готовит материалы, но отправка завершается пользователем на hh.ru. Резюме добавляются вручную. Неподдерживаемые возможности не имитируются. Подробная [матрица API и разрешений](docs/HH_API.md), [машинная проверка](docs/hh-api-audit.json).

## Запуск через Docker Compose

Нужны Docker Desktop / Docker Engine с Compose и Node.js 22.13+ для генерации окружения (либо создайте `.env` вручную из `.env.example`). Поддерживаются Windows, Linux и macOS; команды выполняются в корне проекта.

```sh
node scripts/init-env.mjs
docker compose up --build -d
```

Откройте http://localhost:3000. Нажмите «Первый запуск? Создать аккаунт». Используйте значение `REGISTRATION_CODE` из локального `.env`. Регистрация без этого кода закрыта. Укажите свою email-почту: на неё будут приходить уведомления.

PostgreSQL и Redis имеют healthcheck и постоянные volumes. Миграции применяет отдельный одноразовый сервис до запуска web/worker. Порты открыты только на loopback. На VPS используйте HTTPS reverse proxy, настройте `APP_URL` и `HH_REDIRECT_URI` на внешний HTTPS-адрес. Cookie становится Secure при HTTPS. Не публикуйте PostgreSQL/Redis в интернет.

```sh
docker compose logs -f web worker
docker compose ps
docker compose down
```

`down` сохраняет volumes. Для обновления: резервная копия → обновление исходников → `docker compose up --build -d`. Секрет ENCRYPTION_KEY должен оставаться прежним; потеря ключа делает сохранённые токены и пароли SMTP нечитаемыми. Копируйте `.env` отдельно защищённым способом.

## Запуск для разработки

```sh
npm ci
node scripts/init-env.mjs
docker compose up -d postgres redis
npm run db:migrate
npm run dev
```

В отдельном терминале:

```sh
npm run worker
```

Worker обязателен для расписания, очередей и email. Он загружает `.env`. Для production вне Docker: `npm run build`, затем `npm start` и `npm run worker` под менеджером процессов. Требуется Node 22.13+. Сборка использует стабильный webpack: в ограниченных окружениях Turbopack может требовать недоступный служебный порт.

## Настройка hh.ru

1. Зарегистрируйте приложение на https://dev.hh.ru. Проверьте условия hh.ru и возможность доступа для вашего приложения.
2. Укажите callback `http://localhost:3000/api/auth/hh/callback` для локального запуска либо точный production HTTPS URL.
3. Заполните `HH_CLIENT_ID`, `HH_CLIENT_SECRET`, `HH_REDIRECT_URI`, корректный `HH_USER_AGENT` с контактной почтой. Перезапустите web и worker.
4. В настройках приложения нажмите «Подключить hh.ru», авторизуйтесь **на hh.ru**, дайте согласие. Должен быть аккаунт соискателя.
5. Права определяет hh.ru. В интерфейсе показаны подтверждённые возможности и ограничения, а не вымышленные OAuth scopes.

Пароль hh.ru не запрашивается. Access/refresh токены зашифрованы AES-256-GCM, одноразовый refresh сериализован блокировкой строки PostgreSQL. 401/истёкший refresh приостанавливают работу; 403 конкретного endpoint не обходится. Отключение удаляет локальные токены; отзовите доступ приложения также на hh.ru.

## Первый рабочий сценарий

1. В «Мои резюме» добавьте реальный текст и навыки. Заполните базу фактов: один короткий факт на строку, подтверждения навыков, ожидания и ограничения.
2. В «Поисковые профили» создайте критерии, выберите минимум одно резюме. Можно импортировать параметры ссылки hh.ru. Настройте порог, веса, списки компаний, интервал и режим.
3. В «Настройки AI» сохраните конфигурацию для каждого назначения: ANALYSIS, LETTER, CLASSIFICATION, SCREENING. Укажите реальное название модели, цену и бюджет. Проверьте подключение.
4. Запустите агента в часы активности (по умолчанию 09:00–19:00 Europe/Moscow) и нажмите «Проверить сейчас». По умолчанию включён Dry Run.
5. Изучите реальные вакансии, объяснения, письмо и задачи. Для отправки откройте hh.ru. Приложение ничего не отправляет вместо пользователя через недокументированный механизм.
6. Для реальной истории отключите Dry Run, отправьте отклик на hh.ru и нажмите «Я отправил отклик». Источник USER_REPORTED виден в истории. Последующие этапы отмечайте в табличном режиме «Отклики».
7. Тесты и вопросы можно вставить в карточку вакансии. AI подготовит черновик либо задачу, но не отправит ответы и не исполнит код задания.

Остановка доступна на панели. Уже начатый HTTP-запрос может завершиться. Пауза и перезапуск не стирают записи. Queue concurrency ограничена, повторы конечны, PostgreSQL защищает от повторных откликов между профилями.

## AI и Ollama

OpenAI-совместимый Base URL должен заканчиваться на `/v1` (или эквивалентный префикс провайдера), поддерживать `POST /chat/completions` и `response_format: json_object`. Все ответы валидируются Zod. Невалидный/недоступный AI после ограниченных попыток передаёт вакансию пользователю. Внешним AI отправляются тексты вакансии и ваш профиль: выбирайте провайдера с подходящими условиями обработки персональных данных.

Разрешённые серверные AI-хосты задаёт владелец в `AI_ALLOWED_HOSTS`, exact hostnames через запятую. Произвольные адреса и редиректы запрещены. Не разрешайте недоверенные хосты. Ollama:

```sh
docker compose --profile local-ai up -d ollama
docker compose exec ollama ollama pull qwen2.5:7b
```

В интерфейсе: Ollama, `http://ollama:11434/v1`, модель `qwen2.5:7b`, ключ пустой. Качество и скорость зависят от модели и железа. Модель выбирает 1–3 факта; письмо собирается из них дословно. Для английских писем подготовьте факты на английском — вымышленный перевод опыта не генерируется. Письма длиннее 7 предложений направляются на ручную проверку.

Рейтинг рассчитывает сервер по весам; LLM даёт компоненты и объяснение. Неподходящий формат, валюта, зарплата и blacklist обрабатываются до скоринга. Недостаточная уверенность → ручная проверка. Обратная связь и whitelist входят в контекст следующей оценки. Это контекстное ранжирование, не обучение весов модели.

Цены задаются вручную в USD за 1 млн токенов. Перед запросом резервируется консервативная максимальная стоимость двух попыток. При неизвестном результате/отсутствии usage резерв сохраняется до смены суток UTC, чтобы сбой не обнулял лимит. Это приблизительный учёт, не счёт провайдера. Нулевая цена подходит для локального AI; без цены денежный лимит не защищает от списаний провайдера.

## SMTP

В `.env` внесите SMTP-хост в `SMTP_ALLOWED_HOSTS`. В интерфейсе задайте host/port/логин/app password, адрес отправителя и TLS. Порт 465 использует implicit TLS, 587 — STARTTLS. Пароль зашифрован. Получатель — email пользователя. Без SMTP уведомления сохраняются с UNCONFIGURED, задачи доступны внутри приложения. Уведомления: вопросы, тестовые, сообщения, приглашения, авторизация, пауза, лимиты, дайджест после 20:00 в часовом поясе пользователя.

Повтор SMTP-запроса после сетевого сбоя может дать повторное письмо: стабильный Message-ID уменьшает риск, но SMTP не обеспечивает exactly-once delivery. Нет Telegram-интеграции (опциональна в ТЗ).

## Структура

- `src/app` — страницы, session API, OAuth.
- `src/components` — русскоязычное рабочее пространство, формы, графики, таблицы и kanban.
- `src/server/hh.ts` — проверенный адаптер hh.ru; отправка соискателем запрещена.
- `src/server/engine.ts` — scanner, скоринг, письма, handoff, вопросы, сообщения, расписание.
- `src/server/worker.ts` — 7 очередей BullMQ, ограниченная concurrency и retries.
- `src/server/ai.ts` — совместимый LLM, JSON-валидация, резервирование бюджета.
- `prisma` — нормализованная схема и SQL-миграции.
- `tests`, `e2e` — unit, PostgreSQL/Redis integration и браузерные тесты.
- `docs` — API, матрица hh.ru, план и результаты проверок.

[Контракты API](docs/API.md). `GET /api/openapi` возвращает OpenAPI 3.0 для Swagger. SSE обновляет запросы TanStack Query при появлении событий. Формы проверяются повторно на сервере. HTML описаний отображается как текст; произвольный код и инструкции вакансий не исполняются. Сессии — случайные 256-bit токены, в БД хранятся только SHA-256, срок 7 суток. API проверяет владельца записи. Изменения защищены Origin/SameSite; ORM параметризует SQL. CSV защищён от формул.

## Тесты

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Для интеграционных тестов нужна отдельная БД с именем, заканчивающимся на `_test`. Не направляйте их на рабочую базу. Передайте `TEST_DATABASE_URL` и примените миграции к этой базе. Значение по умолчанию для тестов: PostgreSQL `127.0.0.1:55432/jobhunter_test`; тесты создают и удаляют только собственные записи.

```sh
npm run test:integration
```

Для E2E запустите web и worker на тестовой базе, задайте REGISTRATION_CODE в `.env` и установите браузер:

```sh
npx playwright install chromium
npm run test:e2e
```

E2E регистрирует отдельного пользователя с адресом `@test.invalid`, создаёт тестовые резюме/поиск и проверяет интерфейс. Реальные отклики не отправляются. [Результаты проверок](docs/TEST_RESULTS.md).

## Границы готовности

Исходники, миграции, Docker Compose и работающие локальные сценарии предоставлены. Перед эксплуатацией на VPS нужны реальные OAuth credentials, проверка доступа hh.ru, AI и SMTP, HTTPS, резервное копирование, мониторинг и проверка применимых условий обработки данных. Полная автономная отправка и автоматические статусы соискателя не заявляются работающими. Реальный OAuth/чаты/SMTP провайдера нельзя подтвердить без ваших разрешений и конфигурации. Ограничения и фактически выполненные проверки отражены отдельно, а не скрыты за демоданными.

Параметр тестового Redis — `TEST_REDIS_URL` (по умолчанию `redis://127.0.0.1:56379/15`). Для тестов очередей используется отдельный Redis на порту 56379. SMTP/AI тесты создают контролируемые локальные серверы, настоящие ключи не используются.

AI-рекомендации в аналитике доступны по кнопке после 30 откликов в каждом из минимум двух профилей. Модель получает только агрегированные данные; ссылки на выборки и их размеры проверяются. Результат не доказывает причинную связь.

Полный [перечень реализованных функций и границ](docs/FEATURES.md). Для большого объёма истории dashboard ограничен последними 10 000 записями, экспорт — 50 000 строками; API помечает ограничение полем `truncated`. Это приложение для персонального поиска, не сервис массовых откликов.

Фоновые запросы hh.ru дополнительно распределяются общей блокировкой PostgreSQL с интервалом `HH_REQUEST_INTERVAL_MS` (по умолчанию 500 мс, допустимый диапазон 500–5000 мс). При переполнении ожидания задача использует ограниченные повторы. 429 и Retry-After площадки продолжают действовать независимо от локального ограничения.

Для воспроизводимого запуска интеграционных тестов на Windows, Linux и macOS:

```sh
docker compose -p jobhunter-tests -f compose.test.yaml up -d --wait
node scripts/run-integration-tests.mjs
docker compose -p jobhunter-tests -f compose.test.yaml down
```

Этот отдельный Compose использует временные PostgreSQL/Redis на портах 55432/56379 и не подключает рабочие volumes. Тестовый пароль в compose.test.yaml — открытая фикстура, не пароль рабочего сервера. Скрипт сам генерирует Prisma Client и применяет миграции к тестовой БД. `TEST_DATABASE_URL` и `TEST_REDIS_URL` позволяют указать собственные изолированные сервисы; имя БД обязано заканчиваться на `_test`.

При смене адреса/типа AI-провайдера сохранённый API key очищается, если новый ключ не введён. То же правило применяется к SMTP при смене host, порта или пользователя: пароль не переносится на другой сервер автоматически. Настройки и секрет обновляются под блокировкой пользователя, чтобы параллельные сохранения не смешивали адреса и учётные данные.

В общей записи вакансии сохраняются только разрешённые публичные поля. Неизвестные поля ответа hh.ru, контакты и пользовательские метаданные не копируются в общий raw JSON.

Внешние AI-провайдеры требуют HTTPS. HTTP разрешён только хостам из `AI_HTTP_ALLOWED_HOSTS` (по умолчанию Ollama/localhost/127.0.0.1), которые также должны входить в `AI_ALLOWED_HOSTS`. Для Ollama на другом узле локальной сети владелец явно добавляет его в оба списка.
