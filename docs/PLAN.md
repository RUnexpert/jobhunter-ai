# JobHunter AI — архитектура и план

Проверено 27.10.2026. Пустой проект; Next.js App Router объединяет UI и API. Отдельный worker использует ту же бизнес-логику, PostgreSQL — источник истины, Redis/BullMQ — доставка задач. ## Ключевое решение по hh.ru

Текущая public OpenAPI не содержит POST /negotiations (отклик соискателя) и GET /resumes/mine. Старые markdown-ссылки на эти операции не подтверждают их доступность. POST /negotiations/response также отсутствует: GET с таким путём — коллекция работодателя. Поэтому отправка и автосинхронизация резюме заблокированы на уровне адаптера, резюме вводится пользователем, отклик открывается на hh.ru. Автоматический режим готовит материалы, но передаёт пользователю неподдерживаемую операцию. APPLIED выставляется только после явного ручного подтверждения с источником USER_REPORTED. Не реализуем недокументированный endpoint или браузерный обход.

## Интерфейс

Рабочее пространство: спокойный холодный фон #f5f7fb, текст #172338, синий #335cff, зелёный #19856f, граница #e4e9f2, белый #ffffff. Системный sans-serif без сетевой загрузки; табличные цифры. Слева тёмно-синяя навигация, сверху состояние агента, в центре плотные данные и осмысленные пустые состояния. Уникальный акцент — полоса этапов поиска и видимый режим безопасности. Ровное выравнивание по левому краю; графики и таблицы без декоративных иллюстраций. Рецензия: KPI-карточки нужны по ТЗ, остальная информация сгруппирована в таблицы и линии процесса, без одинаковых карточек для каждого блока.
